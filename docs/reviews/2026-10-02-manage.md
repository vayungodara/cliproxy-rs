# Config and Management API review (ultra/manage, 2026-10-02)

Review of the config/management subset merged at `794b2b8` against CLIProxyAPI
`6fecc6e`. Go code is the reference; expected values in the tests come from the real
Go handlers (`crates/cpa-server/tests/reference/manage`). Status is per increment.

## Access rules (fixed in increment 1)

1. Local/remote: Rust treated any loopback address (`127.0.0.0/8`, mapped forms) as
   local and never consulted `trusted-proxies`. Go compares the gin client IP text
   with exactly `127.0.0.1` or `::1`, after trusted-proxy resolution of
   `X-Forwarded-For` then `X-Real-IP`.
2. `server.trusted-proxies` was neither parsed nor validated. Go rejects empty,
   padded and unparsable entries at load with specific messages, and applies the
   list at startup only.
3. Bans: Go checks an active ban first, bans on the fifth counted failure (missing
   or wrong key), keeps counts until success, ban or a 2 h idle purge, and reports
   `IP banned due to too many failed attempts. Try again in 30m0s`. Rust banned on a
   rolling window, reset counts after 30 minutes, and omitted the remaining time.
4. Availability: with no secret Go serves a bare 404 from its availability gate;
   `MANAGEMENT_PASSWORD` keeps routes on; a `--password` alone enables routes until
   the first reload, and the middleware then still answers 403
   `remote management key not set`. Rust answered `{"error":"not_found"}` from the
   auth middleware and had no `--password`.
5. Headers: `X-CPA-SUPPORT-PLUGIN` was `false` (Go: `0`/`1`), `X-CPA-COMMIT` and
   `X-CPA-BUILD-DATE` were missing, `Cache-Control: no-store` was sent everywhere
   (Go: config reads only), and JSON lacked gin's `; charset=utf-8`.
6. Routing: unknown paths returned an authenticated 501, wrong methods 405 with an
   `Allow` header, and HEAD was served by GET. Go answers all three with a bare 404
   before authentication.
7. CORS: Go's global middleware adds four CORS headers to every response and ends
   every OPTIONS request with 204 before routing. Rust had none, so a cross-origin
   dashboard could not connect.
8. Non-UTF-8 key bytes were dropped instead of compared as bytes.

Not reproduced: gin's trailing-slash redirect (`DELETE /v8/management/config`
returns 307 to `/config/` in Go; 404 here).

## Credentials (fixed in increment 1)

9. Config API keys (`gemini`, `interactions`, `claude`, `codex`, `xai`, `meta`,
   `openai-compatibility`, `vertex`) never became runtime credentials. They are now
   synthesized with Go's IDs, labels, attributes, metadata and sanitizers, and
   republished on every management write and watcher reload.
10. Auth-dir loading missed Go rules: case-insensitive `.json`, trimmed lowercase
    `type`, `gemini` skipped as `gemini-cli`, metadata key aliases normalized,
    invalid weights rejected, and the attributes the scheduler reads (file
    priority, weight, note, headers, prefix, excluded models merged with
    `oauth.excluded-models`, Codex plan type).
11. The interim listing showed config API keys as `runtime_only` and used the
    credential ID as `auth_index`; Go lists file/runtime-only auths only and derives
    a sha256 index.
12. `oauth.request-scoped-errors` never reached the scheduler policy.

## Oracle review of increment 1 (fixed unless noted)

- High: forwarded headers were decoded with `to_str()`, so a non-ASCII entry left of
  a valid client address made the whole header unusable and a trusted loopback peer
  became the client: remote requests were treated as local. Parsing is now
  byte-wise, right to left, exactly like gin. Go fixtures added.
- High: an unreadable `auth-dir` aborted publication, leaving a rotated or removed
  management secret active. Go treats a failed `ReadDir` as an empty file set; the
  config, availability and API-key credentials now always publish. The watcher no
  longer stalls on an unreadable auth dir.
- Medium: file credentials carry Go's normalized prefix, exclusions and aliases in
  attributes, but `scheduler.rs` reads raw metadata. The prefix attribute is now
  always present for files, so a rejected raw prefix can no longer be used.
  Open (scheduler owner): read `attributes.excluded_models` (comma-joined, includes
  `oauth.excluded-models`) and `attributes.model_aliases` (sanitized JSON) before
  metadata.
- Low: zoned IPv6 peers now yield Go's empty client IP; `MANAGEMENT_PASSWORD` is
  read and trimmed as bytes.
- Decision kept: Go's default trusts no proxy, so a loopback tunnel makes every
  client local. Behaviour stays Go's; a one-time warning names the fix
  (`server.trusted-proxies: [127.0.0.1, "::1"]` and a restart).

## Config (increment 2)

Fixed, with expectations from Go's real `ConfigV8` handler (44 replayed steps):

13. Reads now archive unrecognised sections the way Go's read-time migration does:
    they disappear from JSON and appear as `# path: value` foot comments in the YAML
    view; the first write persists that archive and writes no longer fail on them.
14. The first write to a legacy file migrated into JSON-flow sections and dropped
    every comment. Legacy root entries now move under their v8 parents with their
    own lines (head and inline comments, value bytes), re-indented, in block style;
    new root sections are block YAML placed before the foot-comment archive. A value
    equality check falls back to the generic writer for unsupported syntax.
15. Errors carry Go's `message`; `read_only_field` names the `field`; comment-only
    YAML bodies are `invalid_body`; numbers in string fields are accepted.
16. DELETE prunes ancestors the removal emptied; written subtrees get Go's typed
    projection (null to zero on non-pointer scalars, scalars to strings in string
    fields) and the OAuth map sanitizers.
17. TURN credentials omitted from JSON writes are preserved by matching `urls`.

Deliberate differences: Go's saver re-encodes the whole file (four-space indent,
moved comments) and materializes about 30 default keys plus zero-valued struct
fields on every write; cliproxy-rs writes only what changed so untouched keys stay
byte-stable, as the owner requires. Go's load-time rewrite that deletes conflicting
legacy keys is not done; Rust ignores them at load and the first write removes them.
Comment text for archived sections uses two-space YAML.

Open: Go defaults and validation in the typed view (credential concurrency,
in-flight, live-media relay, discovery, retention clamps); watcher timing and a
missing config file.

## Credentials API (increment 3)

Routes: `GET/POST/DELETE /credentials`, `GET /credentials/download`,
`PATCH /credentials/status`, `PATCH /credentials/fields`,
`GET /credentials/models`, `POST /credentials/refresh`,
`POST /routing/cooldown/reset`, `GET /routing/model-definitions/{channel}`, and
the v0 `/auth-files*` and `/model-definitions/{channel}` aliases. A Go replay
(51 steps against Go's handlers and file token store) compares status, body,
auth-dir contents, upload bytes and config effects.

18. The listing had no filters, pagination, quota, cooldown or recent-activity
    fields; it now builds Go's `buildAuthFileEntryLocked` entry, including
    `auth_index`, `cooldowns` and 20 ten-minute `recent_requests` buckets.
19. Uploads (raw body or multipart) validate like `buildAuthFromFileData`, then
    persist the way Go's file store does: the raw bytes stay when they are already
    JSON-equal to the canonical form, otherwise the file is rewritten with
    canonical keys, `disabled` and `json.Marshal` key order.
20. Status toggles on config API keys add or remove `*` in that key's
    `excluded-models`, matching `toggleConfigAPIKeyExcludedAll`.
21. Field patches write `disabled` as Go's store does and follow
    `PatchAuthFileFields` for dotted paths, weight, request retry and headers.
22. File credentials lacked Go's Kimi attributes. `domain` and `base_url` are now
    kept, the domain is canonicalized, and the base URL defaults from the resolved
    domain. Go's quirk is kept: an unknown domain becomes `kimi.com` even when the
    base URL resolves to kimi.ai. The Codex `plan_type` branch already matched;
    these are the only provider branches in Go's `FileSynthesizer`.

Deliberate differences:
- `created_at` and `updated_at` report the file's modification time; the store
  keeps no synthesis timestamps.
- No `status_message`; the runtime does not track per-credential status text.
- `POST /credentials/refresh` refreshes only when due; a forced refresh needs a
  force flag in the executor preparation contract.
- `GET /credentials/models` and the cooldown-reset fallback use the static
  catalog; Go reads its dynamic registry (owned by the routes/registry stream).
- The config status toggle writes the key's own list; Go regroups keys.

## Oracle review of increments 2 and 3 (all fixed)

1. A multipart part with an empty header block panicked the handler; quoted
   filenames with `;` were cut. The hand parser became a port of Go's
   `mime.ParseMediaType`, `mime/multipart` and `textproto` header rules
   (`management/multipart.rs`), pinned by 25 Go-recorded hostile bodies and a
   deterministic fuzz test.
2. `null` on a non-pointer scalar was written as its zero value, so
   `oauth.providers.aistudio.ws-auth: null` disabled WebSocket auth where Go keeps
   `true`. Nulls now take Go's pre-decode defaults (`schema::null_default`, 22 Go
   steps); a null `duration` is `0s`.
3. The config-key status toggle located the key in the published config but edited
   the file on disk; after an unpublished external reorder it changed the wrong key.
   It now locates and edits within the same file snapshot.
4. The toggle rewrote the whole `api-keys.<family>` list and dropped sibling
   comments. Sequences are now synced item by item when only mapping items change.
5. OAuth sanitizers ran before validation, turning malformed maps into a 200 that
   deleted data, and every root or OAuth write normalized unrelated maps. The raw
   candidate is now validated first (Go returns 422), and projection and
   sanitizing apply only to the paths the request wrote (a PATCH's leaves; one map
   or one channel). Go re-normalizes every OAuth map on any write; that is a
   deliberate byte-stability difference, covered by a Rust test.
6. `/credentials/fields` rejected config API keys and `type` changes. Config keys
   are now patched in memory with Go's attribute syncs (no file, no config write);
   a `type` change rewrites the file and re-synthesizes.
7. Uploads no synthesizer claims disappeared from the inventory. They are now kept
   as Go's fallback auths (`credentials::upload_fallback`, provider `unknown` or the
   raw type) until restart, written enabled as Go's store does.
8. Kimi URL classification ignored URL errors outside the authority. A port of Go
   1.26 `url.Parse` acceptance (`config/go_url.rs`) now decides, also used by the
   live-media-relay check.

Also added from Go's `ParseConfigBytes`: `CredentialInFlightConfig.Validate` and
`CodexLiveMediaRelayConfig.Validate` with Go's messages (`config/validate.rs`, 31
Go load cases), `status_message: disabled via management API`, and Go's
`AuthKind` for `account_type`.

## Oracle follow-up on the fixes (all fixed)

1. `parse_duration` could overflow (`u128::MAX…ns1s`); it now follows Go's
   `leadingInt`/`leadingFraction` bounds exactly.
2. Live-media-relay checks could overflow on hostile ports or `max-sessions`. Ports
   are range-checked as Go `uint16` (even when disabled) and `max-sessions * 2`
   wraps like Go's `int`.
3. With a relative `auth-dir`, an upload's absolute fallback path never matched
   the scan's relative path, leaving a duplicate credential after a `type` patch.
   Fallback IDs and retirement now compare lexical absolute paths.
4. `replace_config_backed` did not bump the store epoch, so the registry cache
   kept stale registrations after a prefix patch.

## Dashboard probe contract

The dashboard detects actions with requests Go rejects with 400 before any I/O.
`dashboard_probes_are_rejected_without_side_effects` replays Go's nine recorded
probes: the five implemented routes (`POST /credentials`, `POST
/credentials/refresh`, `PATCH /credentials/fields`, `DELETE /credentials`, `POST
/routing/cooldown/reset`) answer Go's exact 400 with the auth dir, config and
credential revisions unchanged; `POST /requests/api-call`, `POST /oauth/import`,
`GET /oauth/auth-url` and `GET /observability/usage/queue` stay empty 404s until
built, and the test switches to the 400 check as soon as one answers.

## Integration on fe24b8f and cc00c27

- `Runtime::refresh_credential` now forces preparation through the new revision
  argument of `prepare_credential`, as Go's `RefreshAuthFile` does.
- `/credentials/models` and the cooldown-reset fallback read the dynamic registry's
  registrations (`registry::models_for`, Go `GetModelsForClient`).
- `Config.oauth_only` records v8 `oauth.providers.*` leaf paths present in the
  source text (Go `OAuthOnlyFields`, six Go cases); `Config::for_api_key()` is Go's
  `ForAPIKey` view with those fields zeroed. As in Go, the first migrating write
  moves legacy root provider settings under `oauth.providers`, making them
  OAuth-only from then on. YAML merge keys (`<<`) are not expanded (Go expands
  them); anchors and aliases are.

## Increment 4: latest version, usage, api-call

Routes: `GET /server/latest-version`, `POST /requests/api-call`,
`GET /observability/usage/api-keys`, `GET /observability/usage/queue`, and the v0
aliases `latest-version`, `api-call`, `api-key-usage`, `usage-queue` and
`reset-quota`. A Go replay (27 steps, with a local echo upstream on each side)
compares api-call's validation, token substitution, outgoing request (method,
headers, Host override, body, redirect handling) and relayed response.

- api-call decodes its body as gin's `ShouldBindJSON` does (first JSON value,
  case-insensitive field names, type mismatches rejected), validates URLs with the
  Go `url.Parse` port, uses the request, credential or global proxy and otherwise
  connects directly, and sends through the shared Go net/http client
  (`cpa_exec::proxy::send_request`, a method-generic form of `send_routed`).
- `server/latest-version` asks the URL in `observability::LATEST_RELEASE_URL`, empty
  until the cliproxy-rs repository exists; until then it answers Go's
  `request_failed` 502 without any network call (integrator decision).
- The usage queue (`usage::UsageQueue`, Go `redisqueue`) is enabled with the
  management routes, filtered by `usage-statistics-enabled` and pruned by the
  clamped retention.

Deliberate differences:
- api-call does not refresh antigravity, meta or xai tokens before substitution
  (no such executors yet); the stored token is used.
- api-call bounds the upstream body at 64 MiB.
- Nothing enqueues usage records yet: the request path must serialize Go's
  `queuedUsageDetail` and call `Runtime::usage_queue().enqueue` (server thread).
- No RESP subscribers or error queue.
