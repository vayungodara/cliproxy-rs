# v0 management goldens

`../../fixtures/legacy_go.json` holds Go's answers to the v0 management routes
(`/v0/management/...`) at CLIProxyAPI `6fecc6e`, recorded by `main.go` through a
complete `api.NewServer` behind `httptest`: exact status and body for every request,
the exact `GET /v0/management/config` body after every write, and for v8 files the
key-group names in the saved file after every write. No sockets are
opened and no provider, GitHub or OAuth endpoint is called; secrets are `fake-*`.

`src/management/legacy/shape.json` is generated by `shape_fixture_test.go`: the JSON
layout of Go's `Config` (field order, names, `omitempty`, kinds) and Go's
legacy-to-v8 path table. `src/management/legacy/defaults.json` is the recorded
`GET /v0/management/config` body for a config holding only a management key (the
first step of the `reads-minimal` scenario).

Both generators are overlaid into the reference module, which stays unmodified. Run
them with external network denied (for example inside `unshare -rn` with
`GOPROXY=off GOTOOLCHAIN=local`, after `go mod download`):

```sh
reference=/absolute/path/to/CLIProxyAPI   # at 6fecc6e, Go 1.26
here=$PWD                                 # this directory
crate=$(cd ../../.. && pwd)               # crates/cpa-server
echo "{\"Replace\": {\"$reference/cmd/zzlegacy/main.go\": \"$here/main.go\",
  \"$reference/internal/config/zz_shape_test.go\": \"$here/shape_fixture_test.go\"}}" > /tmp/legacy-overlay.json
(cd "$reference" && go run -overlay /tmp/legacy-overlay.json ./cmd/zzlegacy "$crate/tests/fixtures/legacy_go.json")
(cd "$reference" && CPA_FIXTURE_OUT=/tmp/shape.json go test -count=1 -overlay /tmp/legacy-overlay.json \
  -run '^TestZZShapeFixture$' ./internal/config)
python3 -c "import json; json.dump(json.load(open('/tmp/shape.json')), \
  open('$crate/src/management/legacy/shape.json', 'w'), separators=(',', ':'))"
```

Go's harness registers no credentials, so its key lists carry no `auth-index`; the
Rust replay strips that field and `v0_aliases_match_v8_and_lists_carry_live_auth_indexes`
checks the indexes against the synthesized credentials instead.
